Reviewer Notes — Qiye — Bookmark Desktop 1.2.0

Purpose: an extension-first bookmark desktop for a self-hosted SmartTools v2 server. Single administrator; no Chrome native bookmarks, new-tab override or new permissions.

Setup:
1. Use an isolated test instance with BOOKMARKS_MODE=v2 and a reviewed, synthetic v2 KV document. New endpoints: GET/PUT /api/v2/bookmarks and GET /api/v2/bookmarks/meta. Legacy servers cannot supply editable v2 data. Initialization is a separately authorized maintenance operation, not an extension RPC.
2. In collapsed Advanced settings enter the HTTPS service address; Save address requests origin access before persisting the address. Denial/cancellation must not change it.
3. Open start.html and sign in with the existing administrator or reuse that site's browser session.
4. Test root categories, recursive folders, hidden-item organizing mode, inherited Private, stable-ID moves and explicit cloud save. Only top-level updatedAt changes on an effective server save.
5. Current-page/current-window/all-window collection, clipboard and HTML/JSON exports are retained without redesign. Old website-confirmation import buttons are disabled, not adapted to v2 in this release. Native single-link context-menu capture DOES use v2.

Permissions: tabs, scripting, storage, contextMenus; optional HTTP(S) ranges, granted only for the configured origin. No required all-sites grant, cookies, bookmarks, history, notifications, alarms or unlimitedStorage. Retained dynamic import scripts are limited to the configured backend path.

Authentication: credentials go only to the configured site. Browser-managed HttpOnly/Secure/SameSite=Strict cookies; no direct cookie access or persisted password/token. Logout affects the site's browser session. Cookie policy may block extension login; explain it without weakening flags. Independent /account.html is a static server-configuration guide, with no password-change/recovery/revoke controls. Extension authentication uses /api/v2/auth/* only; old account endpoints return 410. A missing PASSWORD server Secret enables a publicly known default; a signed-in user is warned. Password changes require server environment update and redeploy.

Storage: site URL in sync storage; selected category/sidebar preferences and any retained pending import in local storage. Full administrator bookmarks, including Private, live in extension-origin IndexedDB per site and are shared by homepage tabs and native menus, not synchronized via a browser account. No proactive expiry or encryption claim. Logout, expiry, offline use and permission revocation do not erase the readable local copy. Separate site/all-sites clear controls erase confirmed caches and affected drafts. Uninstall/storage cleanup/failure may lose data. Cloud server cannot revoke downloaded copies. Drafts stay in each page's memory; public responses cannot replace administrator snapshots. Old schema-1 snapshots are read-only and removed for that site only after a confirmed schema-2 cache transaction succeeds.

Privacy: Private is inherited server access control, NOT encryption. New APIs require authentication and private/no-store. No analytics. Bookmark images can contact specified image hosts; clicked destinations open normally. Review only with synthetic data.

Save: exact start.html sender/action allowlist, fresh server authentication, baseEtag conflict checks. Popup, old home.html, query/hash impostors and content scripts cannot save; websites cannot read the full cache. Conflict/network failure keeps the draft, with no auto-retry/full-overwrite fallback. KV version checks are not atomic locks. Cache-write failure is reported separately from cloud success. Root folders and children share stable IDs; moves cannot create cycles or exceed 32 levels.

Context menus: recursive container destinations, current page/link/toolbar capture, duplicate complete URL skipped within the same destination. Latest container identity and effective Private must still match. More than 200 container entries offers a manual homepage entry (does not transfer the clicked URL). Login failure retains menus and cache, but refuses cloud writes; badge/popup provides feedback.

Automated tests: npm run test:extension loads a real unpacked MV3 extension against loopback synthetic API handlers. Only its temporary manifest pregrants loopback access. npm run test:v2 covers protocol and retirement builds/old SW upgrade. These do not certify native permission prompts, OS context menus, third-party-cookie policy or production KV propagation. Verify those manually. No real Private data in fixtures/logs.
