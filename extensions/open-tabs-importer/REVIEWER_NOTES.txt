Reviewer Notes — SmartTools Tabs Importer 1.2.0

Purpose: import open tabs to a self-hosted SmartTools backend, and manage that site's bookmarks/groups in a local extension page. Single existing administrator; not a Chrome native-bookmark manager or a new-tab override.

Setup:
1. Use a SmartTools instance with /api/data?format=structured and baseEtag save support.
2. Configure the HTTPS /config.html URL in the popup or management page.
3. Approve the runtime permission for that origin only.
4. Open the bookmark management homepage and sign in with that instance's admin account (or reuse its browser session).
5. Test groups/cards/subcards, explicit cloud save, and logout. Do not use real Private data for review.
6. Test current-page and window imports. They still open website confirmation; no auto-save.

Permissions: tabs, scripting, storage, contextMenus; optional HTTP(S) host ranges for self-hosted domains. No required <all_urls>, no all-pages static content script, no cookies/bookmarks/history permissions. Dynamic content scripts match only the configured backend path. The claim in older reviewer notes that runtime permission cannot support injection was incorrect.

Authentication: credentials are submitted only to the configured instance. Browser-managed HttpOnly/Secure/SameSite=Strict cookies; no direct cookie access or password/token storage. Logout affects the same site's web session. Third-party cookie policy may prevent extension login; use the website backend rather than weakening cookie flags.

Storage: configured URL in sync storage (may sync with the browser account); pending tab import in local storage until acknowledgement. Complete administrator bookmarks, including Private, are stored per site in extension-origin IndexedDB and shared by the homepage and context menus. There is no proactive expiry or browser-account synchronization of this cache; it is not encrypted. Logout, session expiry, offline use and permission revocation retain a readable local copy, which the server cannot revoke. Separate current-site/all-sites clear controls erase cached data and affected open-page drafts. Uninstalling, browser cleanup or storage failure can lose this cache. Passwords and Cookie tokens are never persisted; unsaved drafts remain in each page’s memory. Images may contact image hosts selected by the bookmark owner; destination pages open only when clicked. No analytics.

Private is access control, NOT encryption. KV writes are eventually consistent; ETag checking detects observed stale saves but is not atomic locking. A conflict retains the draft and never retries as a full overwrite.

Manual checks: approve/deny/revoke native site permission; switch configured sites; session expiry; strict third-party cookie policy; import with backend closed. Automated headless extension acceptance pregrants only a loopback origin in a temporary manifest; it does not certify the native permission prompt.

Additional checks: native page/link/action menu → group → standalone/existing expandable parent; duplicate URL skipped; destination changed/Private transition rejected; badge/popup feedback on unauthenticated capture; restart/offline/logout retain Private; clear current/all sites; drafts are not cached; no automatic retry/polling. Review only with synthetic data.

Built-in browsing / reorganized manager:
- Popup "打开主页" opens start.html; "书签管理" opens home.html. They reuse separate extension tabs, never override new tabs.
- Browsing uses local search and a category/icon desktop; hidden groups are omitted, cached Private remains visible after logout. Child links open in a single-level folder popover. Manager defaults to a light list and right-side editor with Apply-to-draft, explicit cloud Save and Discard.
- Both pages use the same confirmed cache. Unsaved manager edits do not appear in start.html. start.html additionally has version-checked save access, but cannot initialize static data. Exact page URLs and action allowlists reject content scripts and unknown actions.
- No additional permissions. All scripts/styles/UI icons are local; the desktop uses system fonts and the existing Fjalla One resource is retained; font license in fonts/OFL.txt. No reference product branding or screenshots are shipped.
- Run npm run test:extension against isolated local Pages for dual-page and responsive acceptance. Native OS menu/permission prompts still require manual verification.

Icon-desktop homepage update:
start.html now offers category navigation, single-level folder popovers, local search, context/keyboard menus and left-button drag ordering/movement. Each page owns independent unsaved memory drafts; only explicit cloud saves update shared IndexedDB. Search disables dragging; folders cannot nest. Static/no-KV data is read-only here; home.html alone confirms initialization. Exact page/action checks deny query-string lookalikes and popup saves. Source/version conflicts retain drafts without retry. No permissions, remote runtime or new-tab override added. Per-origin selected-group keys are UI preferences in local storage, not bookmark content. Test fixtures and reference screenshots are not packaged.
